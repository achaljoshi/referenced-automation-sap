# Changelog

## Unreleased

### Fixed (audit 2026-10-10)
- **SAP-01** One SAP window, one worker: `playwright.config.ts` sets `workers: 1` / `fullyParallel: false` whenever attach mode can reach a real SAP (an env `WORKERS` is ignored with a log line; honoured for the simulator and `SAP_GUI_MODE=open`), and the `sap` fixture refuses attach mode when Playwright runs more than one worker.
- **SAP-02** Idle detection: after an action that should reach the server the session waits for the server's answer (round-trip counter or screen/title/window change, new transport op `progress`) before asking whether SAP is idle, with a bounded quiet period for client-side actions (`roundTripWaitMs` / `SAP_GUI_ROUNDTRIP_WAIT_MS`, default 250 ms, 0 = old behaviour). The simulator (`responseLagMs`) and the stand-in bridge can delay their answer. Verified against the simulator only.
- **SAP-03 (partial)** `scripts/min-executed.js` fails a run that executed too few tests and prints the skip reasons with counts (the JDK-less skip of `javaBridge.spec.ts` is now visible in the CI log); a manual/scheduled `sapgui-conformance` job template runs `npm run conformance` (NOT VERIFIED - nobody has run it). The production transport is still never executed by any test.
- **SAP-04** "Control not found" is decided by what failed (`FindById` failing on a live connection) instead of the English message text (kept only as a fallback); a dead COM connection is the new error code `SESSION_LOST` instead of `null` / `false`; the process transport has a `stdin` error handler, kills the bridge after a timeout and rejects every pending request at once, gives `quit` a 2 s deadline and no longer spends ~93 s on a startup failure.
- **SAP-05** Cleanups run strictly one at a time (a cleanup that times out gets an abort signal and is awaited; if it never stops the rest are reported failed); a failed cleanup fails the test and is annotated; `sap-gui-data` has `--fail-on-orphans` / `--require-data` and exit code 2 for damaged data; `unique()` carries the worker index and a random part.
- **SEC-05** The VBS converter replaces values that flow into a secret field (variables, concatenations), PIN / OTP / token / secret fields and secret-named assignments (`password = "..."`) with environment reads, redacts literals it copies into comments and warnings, and marks every statement inside a `With` on an unresolvable target unsupported (it used to resolve `.text = ...` against the session).
- **ORC-03** *the status bar does not show an error* waits for evidence that SAP has answered and checks E and A (new matcher `toHaveNoStatusError`; the step *... right now* is the instant check); converted tests have no assertion unless `--expect-status` is given and now end with a TODO and a failing guard; `npm run convert*` pass `--strict`, which no longer counts "a secret was replaced" as something to attend to; the committed generated examples assert the status message.
- **SEC-10** Screenshots go under `test-results/sap-evidence` and are deleted once attached; `SAP_GUI_POWERSHELL_SCRIPT_DIR` runs an approved/signed copy of the bridge without `-ExecutionPolicy Bypass`; the DPAPI helper sets UTF-8 on both pipes.
- **U7** `byControlId` is anchored on `--` (and escapes the id); `waitForUI5Ready` fails when a busy indicator never clears.
- **S13 / S14 / CI** `test:smoke` / `test:framework` / `test:bdd` run `bddgen` and the min-executed check; the build job type-checks; the Pages job checks for Java and results; the sample features create orders through `sapData` (unique reference, VA02 delete cleanup) and use the remembered order number.
- **S15** `toMatchScreenContract` refuses to update a baseline when `CI` is set; `fill(..., { checkMaxLength: true })` also reads the value back; `home()` re-checks for a pop-up after `/n`; the `sap` fixture fails when `home()` fails.
- Docs: `docs/ARCHITECTURE.md` no longer claims "125 tests", a future JACOB helper or that nothing is swallowed.

### Changed (behaviour)
- **Stricter defaults** (each has an opt-out): a failed cleanup fails the test (`SAP_GUI_CLEANUP_FAILURE=warn`); a session that cannot return to the start screen fails the test (`SAP_GUI_HOME_FAILURE=warn`); attach mode with more than one worker is refused; *the status bar does not show an error* fails when nothing was observed (`... right now` is the old instant check); converted tests fail until an assertion is added (`--expect-status`, `--allow-no-assertion`); `waitForUI5Ready` throws if a busy indicator never clears; `byControlId('Btn')` no longer matches `SaveBtn`; `toMatchScreenContract` update is refused in CI; `fill(..., { checkMaxLength })` fails when SAP truncated the value.
- A request that times out stops the bridge: the transport is no longer usable afterwards (the session's health check fails and the fixture reconnects). `exists` / optional property reads rethrow a dead connection.
- Each server-bound step costs a few more COM calls and, for an action that never reaches the server, up to `roundTripWaitMs`.
- `sap-gui-data orphans` is unchanged (exit 1 when orphans exist); `list` gains `--fail-on-orphans`.
- `npm run test:framework` and `test:bdd` pass `--workers=50%` (they use the simulator only); the default `.env.dev` / `.env.qa` are `open` mode, so `WORKERS` is honoured there.

### Added
- **SAP GUI on a remote desktop host** (`SAP_GUI_TRANSPORT=remote`): `RemoteTransport` runs the existing PowerShell bridge on the RDP host through the utils remote agent (`remote.getRemoteHost()` + `startProcess` / `send`), with the same line codec and error codes as the process transport (the codec moved to `src/gui/bridgeProtocol.ts`, behaviour unchanged). A request that times out stops the remote bridge and fails every later request fast; an agent that stops answering is `SESSION_LOST` with a hint to keep the RDP session connected and unlocked; a missing `sap` in `REMOTE_ALLOW` is explained. Attach-mode, one worker only (also enforced by `playwright.config.ts` and the `sap` fixture); `sap-gui-doctor --conformance` runs through it and names the transport; the fixture and the CLIs release the remote process and the host. `SAP_GUI_REMOTE_BRIDGE_FILE` runs an approved bridge copy that is already on the host. `.remote-mailbox/` is git-ignored; see `docs/SAP_GUI_GUIDE.md` > "SAP GUI on a remote desktop host". **NOT VERIFIED on a real RDP host with real SAP GUI:** it was tested only against the utils stand-in agent and this repo's stand-in bridge. The stand-in bridge now ignores blank lines like the PowerShell bridge (the remote transport sends one to read the ready line).
- **Converted tests start with `CONSTANTS` and `LOCATORS`**: `sap-vbs-to-playwright` now writes every typed value (secrets and settings as environment getters) and every control id, each named once, into two objects at the top, and the steps only refer to them - a changed input or screen is one edit. `--page-objects` puts both at the top of the pages file; `--inline` keeps the old style. The logon fields are named `logonClient`, `logonUser`, `logonPassword`, `logonLanguage`.
- **BDD (`playwright-bdd` 9.2.1, pinned)**: a `bdd` project and sample features in `features/` (sales orders, test data) running against the simulator, `npm run test:bdd`. `registerSapSteps` now understands `{{placeholders}}` in every string and stores a remembered status-bar value as `{{name}}` too, so steps from the UI and API libraries can use it.
- **Classic SAP GUI framework**: `sap-vbs-to-playwright` (recording -> flat spec, or `--page-objects`, or `--data` for CSV-driven tests), `SapGuiSession` (waits for SAP, retries, journal, evidence, pop-up handlers, health/home/logoff), Playwright-style locators (`getByLabel/Tooltip/Text/Type`, `orElse` fallbacks reported as drift), type-driven `click()`/`fill()`, retrying assertions, grid/tree/table helpers, `SapPage`, screen contracts (`toMatchScreenContract`, `sap-gui-contracts`), the `sapData` registry with guaranteed cleanup, a user pool for parallel workers, secret providers (env, Windows DPAPI), `sap-gui-insights` (transaction coverage, response-time baseline), `sap-gui-doctor` (incl. `--conformance`), reusable BDD steps (`registerSapSteps`).
- Two transports behind one line protocol: PowerShell (default) and Java/JACOB (`SAP_GUI_TRANSPORT=java`, `bridge/jacob`).
- A built-in SAP simulator, stand-in bridges, and 280+ tests with negative controls.
- Docs: `docs/ARCHITECTURE.md`, `docs/SAP_GUI_GUIDE.md`, `docs/MIGRATION_FROM_JAVA.md`.

### Changed
- **`@automation/*` dependencies are version ranges (`^1.0.0`)**, installed from the registry in `NPM_REGISTRY_URL` (`setup` runs `npm config set registry` first); `setup.sh --local` installs locally built tarballs instead; `scripts/publish-package.sh|.bat` publishes this package. README: publishing, upgrading, local generation.
- **Playwright 1.64.0** (was 1.62.1): the `@playwright/test` / `playwright-core` floor is `^1.64.0` and the peer range is `>=1.64.0 <2.0.0` where the package declares one; run `npx playwright install chromium` after upgrading.
- Fiori `waitForUI5Ready` uses no fixed waits; shared Playwright config; lint rules (no hard waits; a warning for raw ids in specs).
